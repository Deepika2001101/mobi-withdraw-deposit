────────────────────────────────────────────────────────────────────────────
 PATCH 3 — SAP Job Scheduler                            OPTIONAL (this is what makes it automatic)
────────────────────────────────────────────────────────────────────────────

Without this, the mail only goes out when somebody POSTs the action. To get
"PO created → approvers are mailed" with no human involved, schedule the action.

Your `mobi_job_scheduler` binding (service-name `mobi_job_dev`) is already in
mta.yaml and already used by the journal-entry reversal job, so no MTA change
is needed — only a new job in the Job Scheduler dashboard.

  Job name        PO_MAIL_NOTIFICATION
  Action          POST
  URL               https://<your-srv-route>/odata/v4/po-mail-notification/triggerPoMailNotification
  Request body    {}
  Schedule        every 5–15 minutes   (cron: */10 * * * *)
  Authentication  OAuth2 (Jobs scope)  — same as the reversal job

  The service keeps a watermark, so each run only picks up POs created since the
  previous run. Running it more often is safe; it never double-mails.

  If the job runs as a technical user, make sure that identity holds the `Jobs`
  scope (xs-security.json already defines `$XSAPPNAME.Jobs` and grants it to
  `mobi_job_dev`). If you later add `@requires` to the action, use:

      @requires: ['OperationsTrigger', 'Jobs']

  exactly like journal-entry-reversal.cds.

 SECURITY — do this before go-live
────────────────────────────────────────────────────────────────────────────

The destination currently stores the mailbox password in PLAIN TEXT as the
additional property `mail.smtp.password`, and that password has been shared in
chat. Recommended:

  1. Rotate the mailbox password for sappostingnotification@mobi.xyz
  2. Put the new password ONLY in the destination's main `Password` field
  3. DELETE the additional property `mail.smtp.password`

PoSmtpDestination already falls back to destination.password / the main
Password property, so nothing breaks. The reason the plain-text property exists
at all is that Type=MAIL + BasicAuthentication does not reliably expose the
main Password field to every Cloud SDK version — after rotating, verify with:

  POST /odata/v4/po-mail-notification/getPoApprovalRouting

and confirm smtpUser / mailFrom are populated, then send one dryRun=false test
mail to yourself.

Never commit the password to git.

────────────────────────────────────────────────────────────────────────────
PATCH 5 - OPTIONAL - switch on the in-app auto run on BTP (zero file edits)
────────────────────────────────────────────────────────────────────────────
If you do NOT want a Job Scheduler job, the app can trigger itself on a
timer (services/PoAutoScheduler.js, off by default):

  cf set-env mobi-cap-srv-<space> PO_MAIL_AUTO_RUN true
  cf restage mobi-cap-srv-<space>

Equivalent mta.yaml variant (module mobi_dev_cap-srv, properties:):

  PO_MAIL_AUTO_RUN: 'true'

Optional companions: PO_MAIL_AUTO_INTERVAL_MIN (default 5),
PO_MAIL_AUTO_STARTUP_DELAY_SEC (default 30), PO_MAIL_AUTO_DRY_RUN (default false).

Do not enable this AND a Job Scheduler job at the same time. With more than
one app instance, deploy the PERSISTED mail log (PATCH 2) first.
